# 脱敏迁移经验：验证（自检页 + 端到端）

本记录来自两次 PHP 传统 Web 应用向 C#/.NET 迁移的案例（A类论坛型、B类 WordPress）。B类部分已标注为 **WordPress 迁移经验**。做法：先把兼容断言做成常驻自检页，再用脚本跑业务全链路，最后用核对表收尾。

## 1. 常驻自检页（如 `/Compat`）

不依赖原 PHP 环境，用 C# 自己证明自己，至少四项：

1. 密码向量：A类断言单公式向量；B类断言示例 md5 向量 + 可移植哈希现算现验往返。
2. 加解密/cookie 往返：A类拼 token 明文 → 对称加密 → 解密比对；B类拼登录 cookie 生成 → 验签往返。
3. 数据库：查版本号 + 读种子行（默认管理员 hash 与描述文件一致且默认口令可验）。
4. 种子：A类用户组行数、默认版块；B类选项表核心键 + 示例文章 + 示例页面。

四项全绿才算“与旧环境互通”，任何一项红灯都不进入业务联调。**回归项**：`/Compat` 本体必须 200（中间件放行表缺失会导致它被改写成内容 slug 而 404，WordPress 迁移经验）。内容过滤、Feed/Sitemap、URL 双模式、选项读取、SEO head（含 og/JSON-LD/canonical/变量替换）建议各加一项断言，共九项。

## 2. 端到端脚本（按机制类型二选一，字段名按实际站调整）

```powershell
# A类：
# 1) 老账号登录：password 先做前端预哈希
# 2) 注册：email/username/password(预哈希 hex)
# 3) 发帖：版块/标题/正文 -> tid
# 4) 回帖：tid/message -> pid
# 5) 旧版 URL 读帖：旧式链接应 200
# 6) 直查库：主题/版块/用户计数回写
# B类（WordPress 迁移经验）：
# 1) 老账号登录：明文 POST（登录字段 `log/pwd`）
# 2) 注册：`user_login/user_email/user_pass` 明文提交
# 3) 评论：POST 原站评论提交路径（字段 `comment_post_ID/author/email/url/comment/comment_parent`）-> cid（未登录/需审核分支各测一次）
# 4) 读帖：`?p=<id>` 与美化 `/年/月/日/<slug>/` 链接均 200
# 5) 搜索 `?s=` 与单页 `?page_id=` 均 200；订阅 Feed 为 RSS/Atom
# 6) 复查帖页评论数与评论体（计数回写）
# 7) 原版专用路径抽查：`wp-login.php`、评论提交路径、`/wp-admin`、`/wp-json/wp/v2` 各 200
# 8) SEO 插件（Rank Math 迁移经验）：文章页含 `og:title` + JSON-LD + canonical + 面包屑；`/wp-admin/seo.php` 保存模板后首页标题即时变化；重定向源路径返回对应状态码 + Location
```

断言点：登录/注册成功、id 递增、新旧 URL 均可访问、计数器与表结构语义一致。

## 3. 收尾核对表

- 自检页全绿（截图或文本留档）。
- 端到端全过；失败项注明是“已知差异”还是“未覆盖”。
- 旧库直挂验证：把生产库复制一份挂到新站，老账号能登录、老帖子能看、老 token 在有效期内可用。
- 输出三类清单：“已验证等价”“已知差异（逐条说明）”“未覆盖（路由/功能）”，作为下一轮的输入。

## 4. A类补充（论坛站迁移沉淀）

- 列名比对脚本：解析安装 SQL 的字段清单，与 `INFORMATION_SCHEMA.COLUMNS` 做**大小写敏感**对比后重建库。某次迁移曾因 ORM 默认 PascalCase 列名导致旧库直挂失败，用此脚本一次性抓出全部 17 张表差异。
- 后台链：后台登录（预哈希）→ 各管理页 200 → 置顶/改密/上传/建用户/搜索/清缓存/改设置逐个 POST 验；设置页写回后首页即时生效可作为配置热更新断言。
- 中文原样输出断言：任取一个含中文的帖子页，正文必须出现原文字符且无 `&#x;` 实体（Razor 默认编码器会转义 CJK，需放开，见前端经验）。
