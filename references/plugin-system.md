# 脱敏迁移经验：插件化（通用机制，Rank Math SEO 迁移经验）

单插件硬编码移植够用，但第二个插件进来就会重复造轮子。通用做法是四件套组合，
Rank Math 就是第一个验证用例（SEO head/面包屑/重定向/后台页全部可挂到下述扩展点上）：

## 1. Hook 事件总线（行为扩展，对标原站 action/filter）

- 核心只做三件事：`AddFilter(hookName, priority, handler)` 注册、`ApplyFilters(hookName, value, ctx)` 串行改值、`DoAction(hookName, ctx)` 通知。
- 迁移时先列原站钩子清单（如 `wp_head`、`the_content`、`wp_robots`、`comment_post_redirect`、`robots_txt`），
  C# 侧在同一位置埋点，插件只订阅钩子不改核心。
- 约定：filter 必须返回同类型值、可叠加；action 只做副作用。优先级默认 10，原站改过优先级的逐个登记。

## 2. 模块装配（IPluginModule + manifest，对标插件目录）

- 每个插件一个程序集（或一个命名空间目录）+ `plugin.json`（id/名称/版本/依赖/最低核心版本）。
- 启动时扫描 `plugins/` 目录：读 manifest → 按依赖排序 → 调 `ConfigureServices` / `MapEndpoints` / `Menu()`。
- 必须支持启用/停用开关（存选项表），停用 = 不调该插件的注册方法，数据表保留。

## 3. UI 扩展点（Zone，对标主题钩子位）

- 布局只留命名占位（如 `head` / `content_before` / `sidebar` / `admin_menu`），插件向占位声明片段，
  按优先级排序渲染。Rank Math 的 head 标签、面包屑、后台 SEO 菜单都是 Zone 消费者。
- 页面级覆盖（如文章 SEO 框）走“视图 partial + 视图模型扩展字典”，不要让插件直接改核心视图文件。

## 4. 存储与配置约定（免建表优先）

- 优先复用现有键值能力：文章级用 postmeta（键前缀 `插件id_`，如 `rank_math_*`）、站点级用 options（`插件id_分组_键`），
  旧库直挂即兼容。
- 独立查询需求（如重定向按源路径查、命中计数）才建专用表，表名沿用原站表名，实体进共享 Entities。

## 5. 移植一个插件的标准步骤

1. 列原插件的钩子/过滤器/后台页/存储键四张表（只列用到的，不管后台 JS/打分等重模块）。
2. 先在核心埋钩子并跑通原有测试（无插件时行为不变）。
3. 把已写死的插件代码整体搬进 `plugins/<id>/`，改成订阅钩子 + 读自有配置键。
4. 补三项验证：停用插件后站点行为回到基线；旧库直挂可用；`/Compat` 加一项“插件头输出存在性”断言。

## 6. 已知取舍

- Hook 总线是动态派发，热点路径（如内容渲染循环）注意只在需要时触发，避免每篇文章触发全量钩子。
- 插件间顺序冲突用优先级 + 文档登记解决，不做自动冲突消解。
- 需要热插拔/沙箱隔离才考虑独立进程或脚本引擎，否则进程内装配足够（当前体量推荐进程内）。
